Numerical Methods ​

This page explains how to set up, integrate, and analyze Parker transport simulations in ParticleTransport.jl, including time-step selection, injection strategies, variance reduction via particle splitting, and how the solver relates to TestParticle.jl.

State Vector, Dimensions & Units ​

Every simulation uses a uniform 4-component state vector

constructed with make_state and inspected with get_position, get_momentum, and get_energy:

julia
julia> using ParticleTransport, StaticArrays

julia> u0 = make_state(SA[1.0, 2.0, 0.0], 1.0);

julia> get_position(u0), get_momentum(u0)
([1.0, 2.0, 0.0], 1.0)

  • Spatial dimensionality (dims = 1, 2, 3): Passed to prepare. Inactive spatial coordinates are masked to zero in both drift and diffusion, so 1D, 2D, and 3D problems share identical kernels and diagnostics.

  • Out-of-place vs. in-place: Passing an SVector{4} to TransportProblem builds an allocation-free out-of-place SDEProblem{false} (recommended for CPU threads and GPU kernels). Passing a mutable Vector builds an in-place SDEProblem{true}.

  • SI vs. dimensionless units: By default prepare uses SI constants for species = Proton (q = Proton.q, m = Proton.m, c = C_SI). For dimensionless benchmarks, pass q, m, and c explicitly (use c = Inf for non-relativistic kinematics  ).

Choosing an SDE Integrator & Time Step ​

TransportProblem returns a standard SciMLBase.SDEProblem, so any solver from StochasticDiffEq.jl that supports non-diagonal noise can be used:

Analytical vs. Gridded MHD Fields ​

Both u and B passed to prepare may be:

  • Analytical functions f(x) (static) or f(x, t) (time-dependent) returning an SVector{3}. Spatial Jacobians, divergences ( ), and curls ( ) are computed automatically via ForwardDiff.jl.

  • Gridded 1D/2D/3D arrays wrapped with build_interpolator (backed by FastInterpolations.jl), which provides analytical interpolant gradients without finite differences.

  • Time-varying MHD snapshots wrapped with LazyTimeInterpolator, which interpolates linearly between consecutive snapshots on demand.

  • nothing (default), representing a zero field with zero runtime overhead.

Particle Splitting for Power-Law Tails ​

In acceleration problems such as DSA ( ), the number of particles above momentum drops steeply (   or faster). Direct Monte Carlo quickly suffers from shot noise in the high-energy tail.

solve_with_splitting implements generational momentum-based particle splitting configured by SplitRule:

  1. Whenever a particle's momentum increases by a factor ratio above its current split threshold, its statistical weight is divided by nsplit and nsplit - 1 identical child particles are recorded at with weight .

  2. After the current generation finishes, the queued children are integrated in the next parallel EnsembleProblem generation (up to max_generations or max_particles).

  3. Exact weight conservation: At every split event,    , so total particle weight is strictly conserved to floating-point precision while boosting statistical counts in the high-energy tail by orders of magnitude.

Boundary Conditions & Streaming Diagnostics ​

  • Spatial & momentum callbacks: Pass TerminateOutside (absorbing / free-escape boundary), PeriodicBoundary, ReflectingBoundary, or MomentumBounds via the standard SciML callback keyword (combining multiple callbacks with CallbackSet).

  • Standard diagnostics: momentum_spectrum and spatial_density accept an EnsembleSolution, a SplittingResult, or a raw vector of states.

  • -memory streaming: For very large ensembles ( ), use streaming_spectrum_ensemble together with spectrum_from_counts to accumulate weighted histogram counts on the fly without storing individual trajectories.
